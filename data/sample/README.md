# Sample data

Small (~50-200 row) illustrative CSVs so you can run and test the pipeline
immediately, without waiting on a Kaggle download.

| File | Rows | What it is |
|---|---|---|
| `transactions_sample.csv` | 190 | Superstore-shaped transaction data, illustrative (not the real Superstore dataset) |
| `customer_master_sample.csv` | 15 | One row per real customer_id above, attributes sampled from a Telco-like distribution |
| `support_tickets_sample.csv` | 24 | Ticket-style text, real customer_id + order-window dates |

**Built-in demo scenario:** East / Corporate customers show a genuine,
reproducible revenue dip — weekly sales drop from a ~$1,553 baseline to
~$580 (a real 62.6% drop) starting 2026-08-10, with 3 matching
pricing-complaint tickets landing on those same customers in that same
window. This is what the Detect → Decompose → Explain scenario in the demo
video should be run against.

**Primary-key integrity:** verified — `customer_master_sample.csv` and
`support_tickets_sample.csv` only ever reference `customer_id` values that
actually exist in `transactions_sample.csv`. Every join in `reconcile.py`
against these files is a real relationship, not a coincidental one.

## This is illustrative data, not the real Kaggle datasets

These CSVs were generated by the same functions in `src/acquire_data.py`
(`build_customer_master`, `build_support_tickets`) that will run against the
*real* Superstore, Telco, and ticket datasets once you run
`download_sources()` with network access — see the main README's Setup
section. The generation script used to build these samples lives in
`docs/generate_sample_data.py` for reference.

For your actual submission, run the real pipeline against the full
downloaded datasets — these samples are a fast way to develop and test
against something concrete in the meantime.
